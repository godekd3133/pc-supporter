# PC Supporter 상용 서비스 준비 프로그램

## 목표

토스의 간결한 정보 전달과 명확한 다음 행동을 참고하되, PC 부품 구매에 필요한 호환성·가격 출처·확인 시각·불확실성은 그대로 드러내는 제품으로 개선한다. 웹/API 운영 모드와 설치 데이터 기반 로컬 모드를 분리하고, 두 경로의 기능 범위와 데이터 소유권을 사용자가 구분할 수 있게 한다.

디자인 기준은 [Toss Design System](https://tossmini-docs.toss.im/tds-mobile/)의 공통 컴포넌트·일관된 상호작용 원칙으로 둔다. PC 구매에 필요한 호환성 근거, 예상 가격 범위, 설치 모드 제한을 축약해 없애지는 않는다.

## 현재 확인된 기준선

- 웹 클라이언트와 Express API는 `pc-supporter` 한 저장소에 있다. 별도 `pc-supporterserver` 경로는 비어 있다. [`server/index.ts`](../server/index.ts)
- Capacitor 앱은 API 주소를 빌드 시 포함한다. 카탈로그 일부는 오래된 세션 응답으로 볼 수 있지만 추천·호환성 계산·저장은 서버 요청이 필요하다. [`scripts/build-mobile.mjs`](../scripts/build-mobile.mjs), [`src/api.ts`](../src/api.ts)
- `DATABASE_URL`이 있으면 PostgreSQL을 유일한 저장소로 사용한다. DB 연결 장애에는 JSON으로 전환하지 않고 readiness 503을 내며, 1초 쿨다운 뒤 같은 프로세스에서 재연결을 시도한다. [`server/repository.ts`](../server/repository.ts), [`server/index.ts`](../server/index.ts)
- 가격 추적의 새로고침은 카탈로그에 저장된 가격을 다시 읽는다. upstream 가격 수집은 별도 scheduler 작업이며, UI에서 원문 확인 시각·출처·오래된 정보 상태를 따로 표시한다. [`src/PriceWatchlistView.tsx`](../src/PriceWatchlistView.tsx), [`server/price-refresh-scheduler.ts`](../server/price-refresh-scheduler.ts)
- 저장 견적은 브라우저가 보관한 ID와 owner token으로 다시 찾는다. 로그인 기반 재설치/다기기 동기화는 없다. owner/recovery bearer tokens는 현재 localStorage에 있어 같은 출처의 스크립트가 읽을 수 있다. CSP 정책은 추가했지만 이를 대체하지 않는다. 상용 공개 전 HttpOnly/server session 또는 platform secure storage로 토큰을 옮기고 재설치·복구 경로를 포함한 자격 증명 설계를 마쳐야 한다. 익명 일별 사용량은 PostgreSQL 모드에서 PostgreSQL에 저장하고, 파일 모드에서만 JSON에 둔다. 기존 JSON 집계는 자동 이관하지 않고 원본 파일을 보존한다. [`src/saved-build-storage.ts`](../src/saved-build-storage.ts), [`src/App.tsx`](../src/App.tsx), [`server/usage-events.ts`](../server/usage-events.ts), [`docs/usage-event-persistence.md`](usage-event-persistence.md)
- 가격 자동 확인과 알림은 앱이 켜져 있을 때의 화면 동작에 기대며, native OS 알림의 백그라운드 실행 경로는 없다. Browser storage는 공용 adapter로 접근하고, denial/quota 때 세션 전용 보존 경고를 띄운다. 손상 견적은 백업을 확보하지 못하면 자동 저장을 멈춘다. [`src/App.tsx`](../src/App.tsx), [`src/native-shell.ts`](../src/native-shell.ts), [`src/safe-storage.ts`](../src/safe-storage.ts)
- 최신 production build는 JS entry 187,591B(55,008B gzip), 첫 화면 전역 CSS 925,757B(127,509B gzip), lazy Admin CSS 41,918B(6,749B gzip), History CSS 70,891B(10,739B gzip), PriceWatchlist CSS 26,333B(4,310B gzip), onboarding CSS 11,102B(2,112B gzip), Catalog/PartPicker 공유 lazy CSS 59,876B(9,249B gzip)다. Admin 404개 rule/449 selector, History 701개/760 selector, PriceWatchlist 222개/261 selector와 Catalog/PartPicker 567개/640 selector 대안을 lazy stylesheet로 옮겼다. Build verifier는 entry JS 600KB, 첫 화면 CSS 1.1MB, 각 lazy CSS 80KB에 더해 HTML entry와 처음 렌더되는 `LazyHomeView`의 정적 JS/CSS closure를 manifest 기준으로 중복 제거해 합산한다. 이번 build의 16개 asset 합계는 JS 580,247B / 178,531B gzip, CSS 925,757B / 127,509B gzip, 전체 1,506,004B / 306,040B gzip이었다(예산: JS 850,000/220,000B, CSS 1,050,000/150,000B, 전체 1,800,000/380,000B). Admin·History·PriceWatchlist·SharedWatchlist·온보딩은 첫 경로 합계에서 제외되는 lazy route로 검증한다. gzip은 로컬 압축 합이며 CDN 전송 크기와 LCP·INP·실기기 frame pacing은 아직 측정하지 않았다. Google Fonts는 CSS `@import` 대신 HTML head stylesheet link와 preconnect로 요청한다. 오프라인 HTML/CSS에는 외부 글꼴 요청이 없는지 build verifier가 검사한다. Admin은 synthetic catalog의 desktop light/dark, History는 합성 저장 견적, PriceWatchlist는 synthetic CPU로 desktop light/dark와 390×844 mobile light를 캡처·검토했다. [Admin light](../artifacts/admin-css-split-verification/screenshots/admin-desktop-light.png), [Admin dark](../artifacts/admin-css-split-verification/screenshots/admin-desktop-dark.png), [History light](../artifacts/history-css-split-verification/screenshots/history-desktop-light.png), [History dark](../artifacts/history-css-split-verification/screenshots/history-desktop-dark.png), [History mobile](../artifacts/history-css-split-verification/screenshots/history-mobile-light.png), [PriceWatchlist light](../artifacts/price-watchlist-css-split-verification/screenshots/price-watchlist-desktop-light.png), [PriceWatchlist dark](../artifacts/price-watchlist-css-split-verification/screenshots/price-watchlist-desktop-dark.png), [PriceWatchlist mobile](../artifacts/price-watchlist-css-split-verification/screenshots/price-watchlist-mobile-light.png). Catalog/PartPicker도 synthetic CPU 데이터로 desktop light와 390×844 mobile light 화면을 열어 필터·목록·가격 안내와 조작 영역을 runtime에서 확인했다. LCP/INP와 실기기 frame pacing은 아직 측정하지 않았다.
- 온보딩 9단계와 대표 분기, 390px 모바일 홈 요약·가격 출처 상세, 데스크톱 홈의 [캡처 manifest](../artifacts/readiness-capture/manifest.json)를 만들고 화면을 검토했다. 실제 PNG 폴더는 `.gitignore` 대상이다. Emulator 밖의 실기기·signed release, 실제 PostgreSQL 기반 공유와 장애 복구 증거는 남아 있다.
- 공유 원본 checkout에는 기존 미커밋 작업이 있다. 이 프로그램의 변경은 격리된 worktree에서 진행하고, 기존 변경을 덮어쓰거나 되돌리지 않는다.

## 작업 순서와 완료 기준

### 1. 저장소와 API 장애 격리 — 코드·테스트 완료, 실제 PostgreSQL 확인 남음

- 파일 저장은 로컬 개발 설정에서 사용하고, PostgreSQL 주소가 지정되면 PostgreSQL만 사용한다. 파일 JSON은 파일 없음일 때만 초기값을 쓰고, 잘못된 JSON과 파일 접근 오류는 요청·저장소 readiness에서 실패 처리해 빈 데이터 저장으로 기존 값을 덮지 않는다.
- PostgreSQL 초기화 또는 요청 중 오류가 나면 파일 저장으로 성공을 가장하지 않는다. 준비 상태와 오류를 API에서 확인할 수 있어야 한다.
- 복구 이후에도 올바른 저장소로 다시 연결되는지 확인한다.
- 완료 기준: 파일 모드 회귀 테스트, PostgreSQL 연결 실패 테스트, 준비 상태 테스트, typecheck와 관련 API 검증.
- 구현 완료: 실패 시 JSON 데이터가 반환되지 않음, PostgreSQL 설정 중 파일 저장이 차단됨, `/api/health`와 실패한 API 요청이 503을 반환함, transient outage 뒤 연결 재시도, 손상/접근 불가 file JSON에서 readiness 실패, 파일 모드 유지, budget-ladder 요청당 익명 `recommend` 집계 1회. Fake Pool, isolated refused port, 격리 파일 fixture에서 검증했다.
- 남음: Compose PostgreSQL round-trip과 실제 설정 환경에서 readiness 복구를 실행해 확인한다. legacy `usage-events.json`은 보존 중이고 명시적 이관 경로가 필요하다.

### 2. 설치 데이터 기반 로컬 모드 — fixture 구현·browser/native emulator smoke 완료, 실제 데이터·release 검증 남음

- 별도의 명시적 빌드 설정으로 선택한 카탈로그 snapshot을 설치 앱에 포함한다. 기본 원격 빌드에는 사용자 로컬 수집 데이터가 들어가지 않는다.
- 번들에는 출처, snapshot 생성 시각, revision, 해시가 들어가며 stale/seed 데이터를 최신 판매가처럼 표시하지 않는다.
- 네트워크가 꺼져도 부품 탐색, 견적 편집, 호환 검사, 추천 결과 확인이 동작해야 한다. 원격 공유·관리자 수집 등 사용할 수 없는 기능은 끄거나 이유를 설명한다.
- 완료 기준: schema·크기 검증, sanitized offline snapshot을 기준으로 한 shared-domain calculation fixture, API 없이 실행하는 browser smoke, Android/iOS 설치 산출물 확인.
- 별도 완료 기준: 로컬 데이터·저장 상태의 내보내기/복원 및 재설치 이후 동작을 설명하고 검증한다. 개인정보를 수집하지 않는 local 모드와 집계만 수집하는 remote 모드는 분리한다.
- 구현 완료: `offline:export --data-dir ... --output-dir ...`가 부품·주변 부품 및 선택된 허용 파일만 읽고, 명시적 snapshot을 만든다. `build:offline --snapshot-dir ...`와 `mobile:offline --snapshot-dir ...`는 빈 Vite env와 명시적 번들을 요구한다. 일반 원격 빌드는 그대로 원격 모드다.
- 내보내기 허용목록은 `catalog.json`, `accessories.json`, 여섯 종류의 알려진 override만 허용한다. 저장 견적, 사용량, 공유·소유/복구 토큰, 크롤러/session 상태, benchmark 수치와 provenance는 결과에서 제외하고 런타임 검증에서도 거부한다. synthetic fixture만 사용해 검증했다.
- 상품 출처 URL은 queryless 경로 또는 숫자 `pcode`만 허용한다. `signature`, `sig`, `key`, `auth`, tracking 및 기타 임의 query 값은 bundle에 넣기 전에 거부한다. Source snapshot revision은 파일 hash와 선택 범주·catalog revision·snapshot 시각을 함께 반영하고, manifest 범주와 파일 행이 다르면 export를 중단한다.
- 공유 domain 계산 경계를 `shared/domain/*`로 분리했다. 원격 서버와 local adapter가 입력 parser, 추천·호환 계산 및 공개 응답 projection을 공유하고, 시간은 명시적으로 주입할 수 있다. 로컬 adapter에는 부품·주변 부품 검색/상세, 핵심·주변 부품 호환 검사, 일반 사양 기반 추천이 있다. 저장 견적 편집은 현재 기기 저장을 사용한다. benchmark/FPS, 성능·출처 확인 필터, 최신 가격 새로고침, 원격 저장·공유, 관리자/수집 경로는 지원하지 않는다.
- 명시적 `PC_SUPPORTER_BUILD_MODE=remote|local-offline`로 두 모드를 분리했다. offline 카탈로그는 JS chunk가 아니라 `offline-catalog.json` 정적 자산으로 설치 앱에 들어가며, 32 MiB 예산을 넘으면 빌드 전 중단한다. 874 KB synthetic catalog로 기존 320 KB lazy chunk 한도를 넘어도 build가 통과했다. offline 번들에는 원격 API 주소, source map, 원격 font 의존이 없고 remote 빌드에는 offline catalog 자산이 포함되지 않는 bundle verifier가 있다.
- Capacitor sync는 임시 native project 복사본에서 실행한다. manifest·catalog·app shell이 Android/iOS 각각 같은 byte인지 검증한 뒤 public asset 디렉터리 두 개를 교체하고, 교체 중 실패하면 이전 디렉터리를 복원한다. sync 실패는 원래 native project에 자산을 부분 반영하지 않는다.
- synthetic snapshot `catalog-0-4ecaecc34937e837`(부품 116개, 주변 부품 43개)로 웹 및 mobile Vite build, Android/iOS Capacitor 자산 동기화, 두 native 플랫폼의 manifest 동일성을 확인했다. 1280px desktop과 390×844 mobile에서 추천·호환 검사 시 `/api` 요청은 0건이었다. 최신 core flow 캡처는 [local-offline verified manifest](../artifacts/local-offline-verified-2026-09-29/manifest.json)다.
- 남음: 현재 검증은 synthetic data, API 호출 차단을 건 desktop/mobile browser flow, Capacitor asset sync, iOS Simulator `.app` build, Android debug APK build와 Android API 36 emulator install/launch까지다. Android release APK/IPA 서명, 실기기 설치, 재설치·복원, app sandbox 저장 용량/손상 복구, 실제 수집 데이터의 최신성 검토는 미검증이다. 생산 snapshot 내보내기는 사장님이 별도 지정한 데이터 경로를 받기 전까지 실행하지 않는다.
- Android debug APK는 임시 경로의 Temurin JDK 21.0.12.1+1과 기존 Android SDK를 프로세스 환경변수로 지정해 빌드했다. APK는 5,355,685B이며 synthetic revision `catalog-0-4ecaecc34937e837`(116 parts, 43 accessories)를 포함하고, 앱 자산 122개가 Android Capacitor public assets와 byte 단위로 일치한다. API 36, 1080×2400 신규 emulator에 설치해 홈과 첫 견적 설정을 열어본 뒤 emulator를 삭제했다. JDK는 시스템에 설치하지 않았다. iOS Simulator 앱은 Xcode 26.6으로 빌드했고, 서명된 IPA와 실제 기기 설치는 하지 않았다. ### 3. 고객 화면과 구매 판단 흐름 — 모바일 홈 정합성·온보딩 접근성 개선 완료, 전체 제품 audit 계속

- 화면은 실제 데스크톱·모바일 실행본에서 단계별로 확인한다. 홈, 첫 견적, 편집, 결과, 카탈로그/상세, 주변 부품, 가격 추적, 구매 목록, 저장 이력·공유의 empty/loading/error/offline 상태를 포함한다.
- Toss와 닮은 색상만 반복하지 않고, 일관된 간격·타이포그래피·상태 표현·전환 규칙을 정한다. 키보드, 스크린리더, 44px 이상 조작 영역, 안전 영역과 reduced-motion 동작을 유지한다.
- 구매 판단 화면에서 예상 금액, 최신성, 출처, 확인 필요 상태를 축약해 없애지 않는다. 모바일 홈과 편집기의 필수 부품 진행률도 같은 계약을 사용한다.
- 구현 완료: 모바일 홈은 editor와 같은 `buildPreflightFor` 필수 수/분모를 쓰고, 첫 네 행에 나오지 않는 SSD·HDD·쿨러·케이스·파워·추가 RAM·주변 부품을 펼쳐 확인할 수 있다. 가격 추적 UI는 카탈로그 읽기와 상품 페이지 가격 확인 시각을 나누며, stale/seed 표시를 보존한다.

### 4. 서비스 경계와 운영 기반 — 감사 및 첫 저장소 개선 완료, scale-out 준비 남음

- 라우트와 데이터 저장, 가격 수집·예약 작업의 책임을 나누되, 첫 단계에서 별도 마이크로서비스를 만들지 않는다.
- PostgreSQL 모드의 rate limit, 익명 사용량 집계, 핵심·주변 부품 catalog, 주변 부품 coverage와 cooling-fan load override는 DB를 사용한다. 파일 mode의 limiter와 catalog는 로컬 또는 단일 인스턴스 용도다. 기존 accessory JSON, coverage 및 fan override 파일은 PostgreSQL로 자동 이관하지 않으므로 배포 전에 승인된 snapshot을 명시적으로 import해야 한다.
- `catalog-ingestion` coordinator를 API와 카탈로그 writer CLI가 공유한다. 예약/manual 가격 갱신, 핵심·주변 부품 crawl 및 retry, 수동 부품 갱신, `import:private-catalog`, `collect-danawa-public-catalog`, `import-danawa-pc9-details`의 apply가 PostgreSQL mode에서 같은 advisory lease를 사용한다. 공개 crawl 함수도 직접 호출될 때 자체 lease를 획득하고, 내부 중첩 호출은 `AsyncLocalStorage` context로 같은 lease를 재사용한다. dry-run은 DB 쓰기가 없어 lease를 잡지 않으며, PostgreSQL 오류는 file lock/store로 fallback하지 않는다.
- PostgreSQL rate-limit bucket은 route scope와 HMAC 처리한 client key를 원자적으로 갱신하고, 저장소/key가 불가하면 요청을 503으로 닫는다. 만료 counter는 공유 lease 아래 batch로 정리한다. Counter는 요청마다 DB upsert를 하므로 실제 PostgreSQL에서 p95 latency·pool wait·write load를 측정해야 한다.
- `combined`(기본 `npm start`), `api`, `worker` process role을 추가했다. API role은 HTTP만 열고 application scheduler/queue polling을 시작하지 않는다. Worker role은 public listener 없이 worker health heartbeat, 예약 scheduler, queue consumption과 기존 monitor/opt-in legacy crawl timers를 소유한다. API/worker split role은 PostgreSQL을 요구하고 없으면 fail-closed 한다. Compose는 API/worker를 같은 Postgres와 `PC_SUPPORTER_DATA_DIR` volume으로 분리하며, 테스트용 두 번째 API replica는 CI 전용 `container-smoke` profile에서만 시작한다. Lightsail은 PostgreSQL 미설정 때 기존 파일 데이터 경계를 유지하는 단일 `combined` process를 쓰고, PostgreSQL mode는 별도 사용자 state migration confirmation이 있어야 API/worker를 분리한다.
- PostgreSQL schema bootstrap은 모든 API/worker instance가 같은 transaction advisory lock을 얻은 뒤 additive DDL을 실행해 first simultaneous startup을 직렬화한다. `/api/health`는 PostgreSQL readiness와 함께 `adminSecurity.productionReady`를 반영하므로 production 관리자 인증이 불완전하면 503이다.
- PostgreSQL `background_jobs`가 이제 price-refresh API/worker flow에 연결됐다. Manual POST는 durable enqueue 후 `202` + job ID/status URL을 반환하며, worker claim은 `price-refresh` kind로 제한한다. UTC interval identity + slot idempotency, missed-slot backlog의 pre-crawl stale skip, optional validated+hashed `Idempotency-Key`, header 없는 active-job 동일조건 dedupe/상이조건 `409`, short exponential retry, 60s lease/20s heartbeat, stale-token fencing, sanitized status/result projection, 90일 retention과 call당 250건 bounded cleanup을 추가했다. Price attempt timestamps는 `price_refresh_attempts`에 공유하고 JSON attempts/status는 file mode에만 쓴다. Schema baseline, runtime DDL, additive migrations 간 align test도 추가했다. [`server/background-job-store.ts`](../server/background-job-store.ts), [`server/price-refresh-worker.ts`](../server/price-refresh-worker.ts), [`server/price-refresh-worker.test.ts`](../server/price-refresh-worker.test.ts)
- API/worker role 분리는 가격 갱신에 한정한다. Core/accessory crawl·retry, 수동 catalog refresh/import는 현재 route와 기존 `catalog-ingestion` advisory lease를 유지하며 queue에 넣지 않았다. Saved-build monitor도 durable queue integration은 하지 않았고, 기존 scheduler는 background owner인 `combined`/`worker`에서만 켤 수 있다. 그 상태/checkpoint/manifest와 여러 accessory override의 file-mode 경로는 이번 변경으로 PostgreSQL shared state가 되지 않는다.
- CI `container-smoke`에는 worker scheduler를 꺼 외부 crawl을 피한 synthetic flow를 추가했다. API POST → worker terminal state → 두 번째 API context status projection, idempotency/kind filter를 확인한다. Recovery phase는 실제 `startPriceRefreshQueueWorker` loop를 child process로 띄우고 주입한 synthetic handler에 들어간 뒤 강제 종료해 3초 lease 만료 후 재claim 및 이전 owner/token write 거부를 확인한다. 이는 외부 price handler와 container restart recovery까지 증명하지 않는다. 각 실행은 고유 Compose project와 계산된 loopback host ports를 사용하고 종료 때 해당 DB/data volume만 제거한다. local Docker/PostgreSQL이 없어 실제 연결 간 검증은 현재 세션에서 `not-run`이고, CI 실행 또한 아직 미확인이다. [`scripts/postgres-price-refresh-worker-smoke.ts`](../scripts/postgres-price-refresh-worker-smoke.ts)
- HTTP 요청에는 무작위 `X-Request-Id`와 route template·상태·처리시간을 담은 JSON 로그를 추가했다. query/body/IP/요청 헤더와 health probe는 남기지 않는다. 프로덕션 log 수집기와 메트릭·알림 연결은 별도 운영 검증이 필요하다. [`server/request-telemetry.ts`](../server/request-telemetry.ts), [`docs/operations-request-logs.md`](operations-request-logs.md)
- Express 응답은 빌드된 CSP meta를 그대로 응답 헤더에 재사용하고 `frame-ancestors 'none'`을 더해, 웹·Capacitor의 script/connect 허용목록을 한 빌드 계약으로 유지한다. meta는 bootstrap script와 다른 script/link 앞에 있어야 하며 build verifier가 그 위치와 SHA-256 theme hash를 검사한다. 기본 출처는 차단하고, 같은 출처 script, Danawa `safeExternalUrl` 허용목록에서 공유한 image host, Google Fonts, 빌드의 API origin만 연다. local-offline 정책에는 원격 API·font·image origin이 없다. 기존 progress·그래프의 동적 style attribute는 허용하지만 inline script와 HTML event handler는 막는다. 함께 MIME sniffing·frame embedding을 막고 외부 referrer를 줄이며 TLS일 때만 HSTS를 보낸다. Owner bearer token은 여전히 브라우저 저장소에서 같은 출처 스크립트에 노출될 수 있다. [`shared/content-security-policy.ts`](../shared/content-security-policy.ts), [`server/security-headers.ts`](../server/security-headers.ts), [`scripts/verify-client-bundle.mjs`](../scripts/verify-client-bundle.mjs), [`vite.config.ts`](../vite.config.ts)
- Cookie-authenticated 관리자 변경 요청과 로그인·로그아웃은 요청 Origin을 same-origin 또는 명시된 허용 origin과 비교한다. Origin이 없으면서 `Sec-Fetch-Site: cross-site`인 요청도 `403 ADMIN_CSRF_ORIGIN_INVALID`로 거절한다. Capacitor opaque origin은 정확한 allowlist 일치로 유지하며, 브라우저가 전달하는 출처 정보로 cross-site form POST를 차단한다. 허용 Origin 설정 오류를 포함한 운영 환경 readback은 별도 배포 검증이 필요하다. CSP와 브라우저 저장소 owner-token의 XSS 노출은 남아 있다. [`server/origin-policy.ts`](../server/origin-policy.ts), [`server/admin-production-config.test.ts`](../server/admin-production-config.test.ts), [`server/mobile-cors.test.ts`](../server/mobile-cors.test.ts)
- systemd `SIGTERM`/`SIGINT` 종료에서는 API listener를 닫아 inflight 요청을 drain하고, price scheduler/queue worker를 멈춘 뒤 PostgreSQL pool을 닫는다. Lightsail 내부 readiness 실패 시 이전 symlink, systemd unit, env file, 새로 추가한 Caddy block을 복원하고 worker의 fresh PostgreSQL heartbeat까지 확인한다. 실제 Lightsail 롤백 rehearsal과 deploy 뒤 public path 장애를 포함한 rollback은 not-run이다.

### 5. 성능과 연출 — 기준선 측정 후 개선

- 기본 원격 앱과 큰 카탈로그를 포함한 로컬 앱의 첫 실행 크기·첫 화면·검색/추천 반응을 따로 측정한다. 과거 결과를 그대로 재사용하지 않고 desktop/390px mobile에서 같은 시나리오를 다시 기록한다.
- 시작 화면에 필요하지 않은 계산 코드와 자료는 분리해 늦게 불러오고, 같은 snapshot/요청은 화면 이동마다 다시 읽지 않는다.
- CTA 이후 진행 상태를 즉시 보여주고, route/modal 전환은 짧고 안정적으로 처리한다. `prefers-reduced-motion` 환경에서는 장식 효과를 줄인다.
- 완료 기준: 현재 bundle budget을 넘지 않거나 새로운 local-data budget을 명시적으로 둔다. LCP·INP·계산 시간의 실제 기준선을 기록한 뒤 개선 여부를 같은 기기와 조건에서 비교한다.
- 첫 화면 draft 저장소 읽기/검증을 App mount 시 lazy state로 옮겼다. production preview의 최대 허용 synthetic draft 114,620B에서 첫 mount read/parse가 각각 1회였고, 같은 화면 App rerender 2회(24ms, 13ms) 뒤 count가 늘지 않았으며 306개 핵심·100개 주변 선택과 저장값을 보존했다. 이 단일 lab probe는 route unmount/LCP/INP 기준선이 아니다.
