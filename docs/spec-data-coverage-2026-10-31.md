# 스펙 데이터 누락으로 생긴 구매 전 경고 정리 — 2026-10-31

자동 견적 결과의 "구매 전 확인할 점"에 데이터가 없거나 규칙이 과민해서 생긴 항목이 섞여 있었습니다. 원인별로 데이터 수집이나 규칙을 고쳤고, 실제 문제일 때만 경고가 남도록 했습니다. 엔진 2.63.0 → 2.64.0.

## 항목별 원인과 조치

| 경고 | 원인 | 조치 |
| --- | --- | --- |
| 메인보드 전원부 용량이 확인되지 않았습니다. | 2.63.0에서 VRM을 CPU 전력 등급/보드 등급으로 판정하도록 바뀌며 문구가 없어졌습니다. | 재발 없음. 표본 견적과 넓은 구간 점검 모두 0건 |
| 메인보드/CPU의 메모리 지원 속도 상한이 확인되지 않았습니다. | 다나와 메인보드 표기 `메모리 8200MHz (PC5-65600)`(대괄호 없음)를 읽지 못해 메인보드 945개 중 193개가 비었습니다. | `parseMotherboardMemorySpeedMhz`가 `[메모리] 8200MHz`, `메모리 속도: 8000MHz`, `최대 8000MHz(OC)`, `DDR5-8000(OC)`, `DDR5 6400/6000/5600`, `PC4-25600 (3,200MHz)`를 모두 읽습니다. 927/945로 늘었고 남은 18개는 원문에 속도가 없습니다(워크스테이션 보드 등). |
| (같은 규칙) CPU 쪽 상한 | 인텔 12~14세대는 다나와에 `DDR5, DDR4 / 4800, 3200MHz`로 적히는데 첫 숫자(DDR4 값)만 읽어 DDR5 CPU 67개의 상한이 3200MHz였습니다. DDR5 XMP 킷이 생성기에서 걸러지거나 "상한 초과" 경고가 났습니다. | `maxMemorySpeedMhzByType`에 세대별 값을 저장하고, 엔진은 RAM 세대에 맞는 값을 씁니다. 원문이 없을 때의 공식 네이티브 속도 표도 보강했습니다(12세대 4800, 13/14세대 i5 non-K 이하 4800, 그 위 5600, 라이젠 9000 5600, 7000/8000 5200, 코어 울트라 200S 6400, 10세대 2666/2933). |
| 케이스 팬을 모두 연결하기 어려울 수 있습니다. | `시스템팬 4핀: 3+1개` 표기를 읽지 못해 X870E Nova 같은 보드가 팬 헤더 1개로 잡혔습니다. 펌프 헤더와 케이스 기본 팬 허브도 반영하지 않았습니다. | `3+1` 합산, `pumpFanHeaderCount`(공랭 쿨러일 때만 케이스 팬 헤더로 셈), 케이스 `fanHubIncluded`(팬허브 기본 제공/허브 컨트롤러 기본 장착)를 추가했습니다. 팬 헤더가 실제로 모자랄 때만 경고합니다. |
| 케이스 조명을 모두 연결하기 어려울 수 있습니다. | 다나와는 RGB 헤더를 종류별로 한 번만 적어(`RGB 12V 4핀 헤더 , ARGB 5V 3핀 헤더`) 헤더 수가 1~2개로 잡히고, 이를 케이스 LED 장치 수와 바로 비교했습니다. ARGB/RGB 헤더 하나에 분배 케이블이나 데이지 체인으로 여러 장치를 묶는 게 일반적이라 실제 문제가 아닙니다. | 장치 수 비교를 없애고, 메인보드에 RGB 헤더가 하나도 없을 때만 경고합니다. 전압(5V ARGB/12V RGB) 불일치는 `case-rgb-voltage`가 그대로 판정합니다. 케이스에 RGB 컨트롤러가 있으면 헤더/전압 판정을 하지 않습니다. |
| 그래픽카드가 두꺼워 옆 슬롯을 가릴 수 있습니다. | 55mm 이상이면 케이스/보드와 무관하게 경고했습니다. ATX 케이스에서 아래 슬롯을 덮는 건 다른 확장 카드를 꽂을 때만 문제입니다. 다나와 GPU 804개 중 157개가 55mm 이상입니다. | ATX 케이스에서는 info("아래 확장 슬롯 N개를 덮습니다")로 내렸습니다. ITX 전용 케이스(55mm 이상), mATX까지만 받는 케이스(4슬롯 81mm 이상), 케이스 규격 미상일 때만 경고합니다. |

함께 고친 것: 예전 수집본에 `radiatorSizeMm: null`이 남은 수랭 쿨러가 있으면 호환성 검사(교체 제안 계산)가 `toLocaleString` 오류로 실패했습니다. reparse에서 null을 지우고 `formatNumber`도 null을 미확인으로 다룹니다.

## 데이터 수집과 반영 경로

- 카탈로그 읽기(`loadCatalog`)가 모든 다나와 행을 `reparseDanawaPart`로 다시 파싱하므로, 배포만 하면 견적과 호환성 판정에 새 값이 쓰입니다. 크롤 재실행은 필요 없습니다.
- 개별 새로고침(`server/part-refresh.ts`)과 크롤러는 `parseDanawaProductPage` → 같은 `parseSpecs`를 쓰므로 새 표기를 그대로 읽습니다.
- PostgreSQL에 저장된 스펙도 맞추려면 `npm run catalog:backfill-spec-coverage`(기본 dry-run)로 변경 수를 확인한 뒤 `-- --apply`로 적용합니다. 저장된 원문에서 읽은 값만 쓰고 가격/updatedAt은 바꾸지 않으며, 적용 전 카탈로그와 변경 로그를 임시 디렉터리에 백업합니다. 로컬 스냅샷 dry-run 결과: 메인보드 메모리 속도 175 / 팬 헤더 47 / 펌프 헤더 386 / CPU 메모리 속도 97(세대별 값 67) / 케이스 팬 허브 12.

## 남은 데이터 공백 (경고 목록에는 안 보임)

- 메인보드 RGB 헤더 미표기 282/945 (B850 Pro RS 등). 원문에 헤더가 빠져 있어 `case-rgb-headers`/`case-rgb-voltage`가 unknown이 되지만, 생성기에서 숨기는 표시용 unknown입니다.
- 메인보드 팬 헤더 미표기 57/945 (A620AM-HVS, B850M AORUS ELITE 등). 같은 이유로 `case-fan-headers` unknown.
- M.2 레인 공유 범위(`m2-pcie-lane-sharing`) unknown은 다나와가 "PCIe 레인공유"만 적고 어느 슬롯인지 밝히지 않아 생깁니다. 제조사 매뉴얼 근거가 필요합니다.
