# PC 서포터 메인 화면 개선

작업일: 2026-10-14

## 요청과 적용

- 노트북픽은 정보 순서와 영역 구분만 참고했다.
- 기존 색상 토큰, 폰트, 토스 스타일을 유지했다.
- 소개 → 추천으로 시작 / 직접 구성 → 견적 진행 상황 순서로 정리했다.
- PC는 두 진입 카드를 가로로, 모바일·앱 공통 화면은 세로로 배치했다.
- 기존 견적이 있으면 이어가기와 현재 부품 구성을 표시한다. 호환 결과, 알림, 저장 견적, 공유와 캐시 관리 기능은 유지했다.
- 새 진입 카드와 중복되는 하단 기능 소개 세 개는 정리했다.
- 섹션은 짧게 나타나며, 버튼은 누를 때 작게 반응한다. 마우스 사용 시 화살표가 이동한다.
- 동작 줄이기를 켜면 홈의 애니메이션과 전환 효과가 꺼진다.

## 담당과 수정 파일

- 메인: `src/HomeView.tsx`, 신규 `src/home-layout.css`, 이 작업 폴더.
- 서브에이전트: 기존 기능·CSS 충돌·검증 항목 읽기 검토. 파일 수정 없음.
- 기존 `src/styles.css`, `src/App.tsx`, 서버·견적 엔진의 다른 작업은 수정하지 않았다.
- 기준 HEAD는 `base-commit.txt`, 최종 변경 파일 해시는 `source-sha256.txt`에 기록했다.
- 수정 전 HomeView는 `HomeView.before.tsx.txt`에 보관했다.

## 검증

- 타입 검사 통과.
- 관련 테스트 4개 파일, 25개 테스트 통과: `tests-final.log`.
- 최종 문구 정리 후 홈 테스트 재확인: `home-tests-final.log`.
- 최종 전체 빌드와 기존 첫 화면 번들 용량 검사 통과: `build-final.log`.
- PC 1440×1000, 모바일 390×844, 320px, 760/761px 화면 경계를 브라우저에서 확인했다. 확인한 너비에서 가로 넘침 없음.
- PC·모바일의 추천 시작은 `/start` 안내 화면으로, 직접 구성은 `/build` 편집 화면으로 이동하는 것을 확인했다.
- 모바일 다크 모드를 확인했다.
- 동작 줄이기 브라우저 에뮬레이션에서 animation `none`, transition `0s` 확인: `motion-check.json`. 검증 후 에뮬레이션과 화면 크기를 초기화했다.
- 정상 화면 캡처: `desktop.jpg`, `mobile.jpg`. 추가 다크·좁은 화면 캡처는 보조 확인용이다.

## 실행 환경과 한계

- 로컬 미리보기: http://127.0.0.1:5175/
- `node docs/home-layout-2026-10-14/preview.mjs`로 격리된 로컬 PostgreSQL과 API 4194, 웹 5175를 시작한다. 데이터는 starter 예시이며 실판매가 검증이 아니다.
- 초기 API 미연결 화면은 최종 시각 증거로 사용하지 않았다.
- 첫 빌드의 용량 초과는 중복 안내 정리 후 해소했다. 용량 제한은 변경하지 않았다.
- 디스크 저장 오류 발생 후 이번에 생성한 dist 소스맵만 정리했다. 소스 온전함을 확인하고 최종 빌드를 다시 실행했다.
- 앱과 웹이 사용하는 공통 UI에 적용했다. 실제 iOS·Android 기기, 네이티브 설치, TestFlight는 확인하지 않았다.
- 커밋·푸시·운영 배포는 수행하지 않았다. 출시하려면 실제 앱 검증과 배포가 남아 있다.
