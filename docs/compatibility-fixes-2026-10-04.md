# 호환성 파서·제조사 사양 보강 검증

작업 시작일: 2026-10-04. 로컬 소스 수정과 로컬 보강 JSON 반영을 완료했다. 운영 PostgreSQL 반영, 커밋, 푸시, 배포는 이 작업의 검증 결과에 포함하지 않는다.

## 수정 내용

- **I-1:** 메인보드 `M.2 연결`에 쓰인 PCIe를 NVMe 지원으로 읽는다. 확장 슬롯에만 PCIe가 있는 경우는 구분한다. 현재 API 수집본에서 NVMe 정보가 보완되는 보드는 **28개**다. 문제 문서에 나온 Z890 Taichi OCF와 ZENITH EXTREME ALPHA 모두 실제 카탈로그 SSD 조합의 잘못된 차단이 사라졌다. NVMe 전용 M.2에 SATA SSD를 고르면 계속 차단한다.
- **I-5:** 단일·합산·범위 페이즈 표기를 읽고, 범위에는 낮은 값을 사용한다. 0·안전한 정수 범위 밖·잘못된 표기는 미확인으로 남긴다. 원문에서 페이즈가 사라지면 오래된 값도 제거한다. 현재 수집본의 보드 **796개**에 페이즈 정보가 생기며, 범위 표기 3개는 모두 11로 읽힌다. 현재 전원부 규칙은 검증된 `vrmCapacityW`를 사용하므로 페이즈를 W로 환산하지 않았다. 원래 보고서의 전원부 ‘확인 필요’ 2건 감소는 재현한 결과가 아니다.
- **I-6:** 라디에이터 위치·크기, 지원 PSU 규격, SSD 베이, 크기별 장착 조건을 보강 경로에 등록했다. 빈 지원 목록은 보완할 수 있고, 기존 사양 및 베이 0은 덮어쓰지 않는다. JSON 저장 후 삭제할 때도 원본으로 복원한다. 누적 필드 수가 저장 한도를 넘으면 저장 전에 거절한다.
- **추가 실제 파서 결함:** `M-ATX(SFX)`에서 `ATX` 부분을 표준 ATX로 읽던 오류와 괄호 안 SFX를 놓치던 오류를 수정했다. `SFX-L`을 SFX로도 읽지는 않는다.

## 제조사 장착 조건

실제 라디에이터 두께, 팬을 포함한 두께, RAM 높이, 실제 라디에이터 폭·길이, GPU 길이를 조건과 대조한다. 확인된 치수가 한도를 넘으면 차단한다. 다른 RAM의 높이가 누락되어 있어도 이미 확인한 모듈의 초과를 숨기지 않는다. 치수가 없거나 브래킷·상판 리비전·조립 모드를 확인할 수 없으면 확인 필요로 남긴다. 특정 조립 모드에 연결된 수치만으로 다른 모드까지 장착 불가로 판정하지 않는다.

H6 Flow 검증에서 27mm 라디에이터는 후면 I/O 설치 조건이 미확인이라 `unknown`, 31mm는 제조사 30mm 한도를 넘어서 `blocker`였다. FLUX의 PSU 커버 위치는 `psu_shroud`로 바닥과 구분하며 화면에는 ‘파워 커버’로 표시한다.

[9개 케이스 근거](case-spec-evidence-2026-10-04.md), [Pop 15개 근거](pop-case-spec-evidence-2026-10-04.md), [Fractal 나머지 31개 근거](fractal-case-spec-evidence-2026-10-04.md)에 원문 링크·리비전·조건·충돌을 기록했다. [55개 일괄 입력 파일](data/case-spec-overrides-2026-10-04.json)은 총 **159개 필드**이며 런타임 검증을 모두 통과했다. 기존 65개 override 중 55개를 로컬 `data/catalog-spec-overrides.json`에 병합했고 원본 백업을 남겼다. 이 로컬 JSON은 운영 PostgreSQL을 자동 변경하지 않는다.

미확인 라디에이터는 Meshify 3 XL 2개, North Mesh 1개, NCORE 100 AIR 1개와 기준 seed 케이스 1개다. 측면 목록이 제조사 자료끼리 충돌하거나 명시된 수랭 근거가 없으므로 부분 목록을 넣지 않았다. Antec 3개의 PSU 규격은 제조사 직접 표기를 확정하지 못했다. 현재 소스에는 `case-ssd-bays` 규칙이 없으므로 SSD 베이 보강을 해당 규칙의 해결로 주장하지 않는다.

## 검증

- 파서·엔진·조건 계산·공유 계약·보강 적용·private importer·관리 입력·표시·검토 필드 회귀: **11개 파일, 373개 테스트 통과**.
- 실제 PostgreSQL의 저장 → 공개 조회 → 원본 보존 → 삭제·복원: **2개 파일, 3개 테스트 통과**. 공개 응답에는 내부 provenance가 노출되지 않았다.
- 전체 타입 검사, TypeScript를 포함한 프로덕션 빌드, 번들 예산 검사 통과. 전체 단위 테스트 모음을 실행한 결과는 아니다.
- 실제 관리 컴포넌트와 실제 validator를 1440px·390px에서 검증. 격리된 카탈로그·메모리 저장소를 사용했으며 조건 JSON이 저장 요청까지 전달됐다. 런타임 오류와 가로 넘침 0건. 운영 화면 저장 증거와 구분한다.
- `git diff --check` 통과. 같은 체크아웃의 견적·온보딩 동시 작업을 보존했다.

## 고정한 300건 검사

현재 공개 API 목록 수집본 **1,803개**를 고정했다. seed는 `20261002`, 엔진은 고정한 현재 소스의 `2.60.0`이다. 원래 2026-10-02 수집본·샘플러가 없으므로 **같은 300건 재실행이라고 부르지 않는다.** 동일 입력과 고정한 엔진을 사용해 이전 파서와 수정 파서·보강 데이터를 비교했다.
